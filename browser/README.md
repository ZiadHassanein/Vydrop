# Vydrop browser companion

## Companion 1.5.0

The Windows installer registers the native connection automatically for the current user. When official store listings are configured, **Settings → Browser integration → Add to Chrome/Edge/Firefox** opens the selected store; approve the browser confirmation and use **Test connection**. Developer mode and folder selection are only needed for the local development companion. Store listings are not published yet. Preview builds retain a separate connection and use the local preview companion.

Firefox 140+ displays built-in consent for browsing activity and website content: selected page/media URLs are transferred to the local desktop app. No analytics or cloud collection is added. Optional stream discovery remains off until its separate permissions are granted.

Companion 1.5.0 adds **Test connection** (keep the app open for a full round trip), **Add to download queue**, and optional media-stream discovery in the popup. Version-1 link sending and existing extension/native-host identities are retained for compatibility.

Discovery is disabled until you grant optional `webRequest` and HTTP(S) host access. It reads media response types/URLs, never cookies, account information, request bodies or media response bodies. Results are bounded per tab/frame, expire after 90 seconds and disappear on navigation or worker restart. Select a listed stream explicitly to send it for inspection; multiple players, ads, MSE, private content, unsupported formats and DRM can still prevent a usable download. Denying or removing the permission leaves normal page/player sending available.

The app can save a link to its queue while busy. Opening a link alone keeps it ready for review; choosing a format and quality and pressing Download explicitly starts that output. A closed app can launch to handle it. Older hosts fall back to the review workflow and retain version-1 sending. Source context lets a waiting job request a fresh URL for the same video. Queue URLs and original pages stay locally for recovery, including in the backup.

To prepare unsigned store-root archives, use `scripts/package-browser.ps1 -StorePackages`. The generated `store-readiness.json` lists remaining publisher account, assigned ID, signing and installed-package tests. These files are **not published or signed add-ons**. Keep the existing unpacked identity; store-assigned Chromium/Edge IDs must be verified and added alongside it to both native origin validation and host manifests before publication.

## Local setup and player behavior

Optional Chrome/Edge and Firefox companions are included in the app ZIP under `Browser`. Normal app downloads need no extension. Companion 1.5.0 places **Download by Vydrop** inside the playing video's top-right corner. Choose Video or Audio, format and quality, then explicitly press Download to start it in the saved app folder. The toolbar popup provides the same choices.

**New to the extension? Follow the illustrated [Chrome](https://ziadhassanein.github.io/Vydrop/browser-extension-setup.html#chrome), [Edge](https://ziadhassanein.github.io/Vydrop/browser-extension-setup.html#edge) or [Firefox](https://ziadhassanein.github.io/Vydrop/browser-extension-setup.html#firefox) guide**, with English and Arabic instructions. The regular **Vydrop** companion connects to the regular app. A separately built **Vydrop Preview** companion uses the preview channel.

In builds with the simplified guided setup, choose your browser in **Settings → Browser integration** and click **Set up Chrome**, **Set up Edge** or **Set up Firefox**. This verifies the app connection, copies the exact extension path and opens that browser's loading page. Complete the loading step there. **Manual setup and troubleshooting** retains the individual page, path, folder and connection actions. If the browser cannot be opened, copy its displayed address manually. A connected status confirms the desktop app registration, not that the browser has installed the extension. If companion files are missing, setup can restore the bundled copy; manual recovery guidance remains available. Browser confirmation is still required.

1. Extract the app ZIP into a permanent folder and open `Vydrop.exe`.
2. Choose **Settings → Browser integration → Enable connection** in the app. This registers the connection for your Windows account only.
3. Chrome/Edge: open the extensions page, enable Developer mode, choose **Load unpacked**, and select `Browser/chromium`. Firefox: open `about:debugging#/runtime/this-firefox`, choose **Load Temporary Add-on**, and select `Browser/firefox/manifest.json`.
4. Play a video and click its **Download by Vydrop** tab. The tab stays visible during playback, follows the largest visible playing video within each frame, and hides when playback stops. It prefers the space above the top-right corner and can use clear space immediately to the right when a header or caption blocks the upper position. Both placements stay outside the picture. If neither position is free, use the toolbar popup. Feedback stays outside the picture; when space is tight, the tab label and tooltip give the result. The toolbar popup and right-click link actions remain available. Finish/cancel any active download before sending another link.

For a companion-only update, extract it into a permanent folder. Chrome/Edge: open the extensions page and reload the existing unpacked companion if its folder was updated in place. If you extracted elsewhere, remove the old companion and load the new `chromium` folder. Keep that folder after installation. Accept the requested website access to show the video button, then reload open video pages. The preview companion connects to the preview app without replacing the accepted app. If the app moved, open its Settings and enable Browser integration again.

Use **Disable connection** and remove the extension to disconnect. Firefox temporary add-ons disappear when Firefox closes. These local-loading packages are not published to browser stores.

Permissions: `activeTab`, `scripting`, `contextMenus`, `nativeMessaging`, `clipboardWrite`. Content scripts run in HTTP(S) pages and embedded frames to locate visible playing video elements and position the button. Only a real user click resolves the link, writes the clipboard and sends it to the local app. There is no cookie access, clipboard reading, account import, analytics or automatic downloading. Detection reads player visibility and nearby public video identifiers/links, not login fields or private app state. Blob playback addresses are never sent as download links.

Facebook, TikTok and YouTube use the selected player's public permalink. On LinkedIn, the companion first looks for a progressive MP4 belonging to that exact player, matching its poster asset against video metadata already in the page DOM. When the newer feed omits this metadata, your explicit click can open the same post in a temporary background tab and inspect its DOM for the matching asset. The companion closes that tab after lookup, unless you navigated it elsewhere. This lets the app inspect a playable media file when LinkedIn gives a guest visitor a sign-up page for the post. The companion does not read cookies, call account APIs, intercept network requests or use paid services. These media links can expire; reopen the video and use the button again to obtain a fresh one. The app measures the media's real video and audio quality. Pasting a post link alone can still fail when LinkedIn does not expose a public video there.

When LinkedIn has no matching progressive media, detection uses the current post's activity attribute or nearby post link; group shares and group-feed links can use their explicit highlighted activity. Detection stops at the current feed card, including the newer list-item layout. A group ID is never guessed to be a video ID. LinkedIn feed and messaging homepages are never sent in place of a video. Facebook timestamps may be warmed through pointer-entry events to reveal their public links, without navigation. Other players use their direct HTTP(S) media URL, a wrapping permalink, or the page URL when there is only one player. Ambiguous feed players produce guidance instead of sending an arbitrary homepage. Hidden/preloaded players are excluded; TikTok's visible canvas-backed player is supported. If opening fails, the error remains available on the button's tooltip until you retry or change videos.

The tab also updates when playback starts after buffering. If a search header occupies its first position, it can use clear space just beyond the player's upper-right corner. In crowded headers it falls back to a compact **V** with the same action, a tooltip and a localized keyboard label; the full text returns when space is available. Nonmodal app suggestions do not hide it; active blocking dialogs still do. If no safe outside position exists, use the extension's toolbar button. LinkedIn downloads require a publicly accessible video and a desktop build with LinkedIn group-link handling; signing into a website does not grant the app access to private posts.

The app validates messages and limits the pipe to the current Windows user. Same-user programs are not an exclusive trust boundary. Website-wide placement does not guarantee every video can be downloaded: DRM, restricted media, closed shadow-root/custom players, browser internal pages, native video fullscreen and picture-in-picture can prevent detection or placement. The app's supported sites still determine download support. A separately built preview companion connects only to the preview app.

Vydrop retains the existing Chromium public key, Firefox add-on IDs, native-host names and website permissions for compatibility. To update an already-loaded unpacked companion, reload it once in the browser, then refresh video pages so the current detection and styling take effect.
